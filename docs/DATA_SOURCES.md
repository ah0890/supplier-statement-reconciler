# Data Sources for Testing

This project is tested **without any confidential data**. This page lists legitimate
sources of test data, what each is used for, and what must never be committed.

## 1. Data in this repository

| Source | Location | Licence / terms | Purpose |
|---|---|---|---|
| Synthetic DEMO dataset generated by this project | `sample_data/`, `scripts/generate_demo_data.py` | Part of this repository; entirely fictional | Demonstrations, end-to-end tests, screenshots |
| Synthetic fixtures built inside tests | `tests/` (CSV text, reportlab-generated PDFs, openpyxl workbooks) | Part of this repository; fictional | Unit and parser tests for messy layouts |
| Layout emulations of common exports (QuickBooks *Vendor Balance Detail*, Sage supplier activity, Xero bills) | `tests/test_real_world_formats.py` | Synthetic values; column structures follow publicly documented export formats | Column detection, grouping, sign conventions |

No third-party documents are committed. All company names, references and amounts in
the repository are invented and labelled **DEMO DATA**.

## 2. Official accounting-system demo data (local testing only)

These provide realistic exports **produced by the real systems**. Generate exports locally,
use them for testing, and **do not commit them**: their terms do not grant
redistribution rights.

| Source | Where | Terms / notes | Purpose |
|---|---|---|---|
| **Xero Demo Company** | Inside any Xero login: *My Xero → Try the Demo Company*. Official help is on [Xero Central](https://central.xero.com/) | Free with a Xero account (including the free trial). The demo data is reset periodically and is visible only to you | Export *Bills* (Business → Bills to pay → Export) and payments to test the CSV/XLSX importer against genuine Xero exports |
| **QuickBooks Online sandbox company** | [Intuit Developer: create and test with a sandbox company](https://developer.intuit.com/app/developer/qbo/docs/develop/sandboxes/manage-your-sandboxes) | Free developer account; sandboxes contain sample data and are for non-commercial development and testing | Run *Vendor Balance Detail* / *Transaction List by Vendor* reports and export them; later, test the planned QuickBooks API integration |
| **Sage** trial / demo company | Through the Sage product the client uses (e.g. Sage 50 demo data, Sage Accounting trial) | Per Sage's trial terms | Supplier activity / purchase ledger exports |

## 3. Supplier statements

There is no well-known, openly licensed corpus of genuine supplier statements, and
public "sample statements" found online usually carry no clear licence. Therefore:

- **Do not** download statements from the web into the repository.
- Use the generated DEMO PDF/XLSX/CSV statements for development.
- For realistic validation, ask the project owner or client for **anonymised** statements
  (see [REAL_WORLD_DATA_REQUIREMENTS.md](REAL_WORLD_DATA_REQUIREMENTS.md)) and keep them
  in `client_data/` or `private/`. Both folders are git-ignored.
- Accounting software can also produce **customer statements** from its own demo
  company (e.g. Xero → Contacts → Send statement → download PDF). These are genuine
  machine-generated statement layouts suitable for local parser testing. They must
  still not be committed.

## 4. Never commit

- confidential or real client documents (statements, invoices, exports)
- documents containing personal data (names, addresses, bank details)
- financial data obtained without permission
- copyrighted documents without a licence that allows redistribution
- local databases (`data/`), uploads or logs

`.gitignore` blocks the usual locations, and `tests/test_security.py` fails if databases,
logs or upload folders are tracked.

## 5. Adding a new external test source

Before using a new source, record it here:

```
Source:        <name>
URL:           <link>
Licence/terms: <licence or terms of use>
Purpose:       <what it tests>
Committed?:    yes (licence allows redistribution) / no (local testing only)
```
